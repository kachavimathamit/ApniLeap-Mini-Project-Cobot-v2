=====================================================================
 ApniLeap Portal - END-TO-END SAMPLE WALKTHROUGH (all 9 roles)
=====================================================================
Follow this top to bottom. Every value to type is given. All names,
numbers and organisations below are fictitious sample data.

You will: add an organisation -> create users for every role -> build
Departments -> create projects with 4-5 student teams ->
fill definition, milestones, KPIs -> raise an issue -> take a project
to RED -> fix it (action, evidence, verification, review) -> return it
to GREEN -> check what every role can and cannot do.

---------------------------------------------------------------------
 0. BEFORE YOU START
---------------------------------------------------------------------
Start the server (from the backend folder):

    npm run db:init
    npm run db:seed        (only once; creates the built-in demo data)
    npm start

Open:  http://localhost:4000

NOTE 1 - Jira/Confluence: if backend/.env has the Atlassian token, every
project you create in Stage 6 also creates a REAL Jira issue (project
KAN) and a REAL Confluence page (space APNI) on your Atlassian site.
Delete them afterwards, or blank the Atlassian values in .env first if
you do not want that.

NOTE 2 - Log in with a different account for each stage. Use "Logout"
(top right) between stages. Log in by typing the password yourself.

NOTE 3 - Dates below are for late 2026. Any future dates work.

Who does what (enforced by the server):
  Platform Administrator .... add institutes; everything else too
  Institute Administrator ... users, departments of ITS institute
  Dean / Dept Head / Mentor / Global Leader ... create projects, change
                              status, milestones, KPIs, actions, team, links
  Reviewer .................. add reviews; verify corrective actions
                              (cannot change status)
  Student ................... signs in with the SRN (default password Demo@12345);
                              sees only their own team's project, read-only
  Read-only Stakeholder ..... view only (cannot even add an issue)
  Red -> Green approval ..... Dept Head, Dean, Institute Admin, Global
                              Leader or Platform Admin (mentor cannot)

---------------------------------------------------------------------
 KNOWN LIMITATIONS (by design in this version)
---------------------------------------------------------------------
- A Dean/Head can
  see only the departments they were given (Users -> Department access).
- Mentors can read every project in their institute. Students see only their own team.
- Students' default password is the same for all (Demo@12345) and there is no change-password screen yet.
- Deleting institutes/departments removes their data in the portal only;
  Jira issues and Confluence pages already created stay on Atlassian.
